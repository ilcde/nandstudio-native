# Android workspace copies (0.1.2 development)

Choose Files > Open workspace, select a folder in Android's document chooser,
and grant access. NandStudio offers **Import copy** before copying anything.
The resulting editable folder is inside the app's private storage. Save, build,
HDL dependencies, relative test paths and all native tools operate on that copy.
The selected original is unchanged. Recent workspaces reopen the local copy.

After saving, choose Files > Export workspace copy and select a destination
folder. Export creates a new `NandStudio-export-...` folder containing saved files
and generated artifacts. It never merges with or overwrites an existing project.
Unsaved documents block export with a console message. Copies exclude `.git` and
`.nandstudio-trash`; other hidden files are preserved. Export important work
before uninstalling the app or changing development signing keys.

Providers are accessed with `content:` URIs through Qt 6.11.1's Android content
file engine, not converted to filesystem paths. Android's folder chooser handles
tree grants. Each export asks for a destination again. Denied/revoked access or
unsupported provider operations report an error; incomplete copies remain at
the reported destination and are not opened as successful workspaces. Direct
provider editing/rename and individual provider-file opening remain incomplete.

Copy limits are 32 MiB per file, 256 MiB total, 10,000 entries and 128 nested
directories. Symlinks and case-colliding filenames are rejected. Files are copied
as bytes, including encoding, line endings and final-newline state. Local saves
use the same conflict detection and atomic-save implementation as desktop.

## Verification

Windows core/hardware tests and 263 GUI assertions passed locally, including
copy byte preservation, original preservation, destination collision, recursive
copy rejection and cancellation. Android compilation and provider interaction
must pass CI before publishing this version. The test uses Android Downloads to
import, edit, save, assemble, export and reopen after process restart, checking
the generated bytes and the unchanged original. A passing result establishes
that scenario only; other providers, grant recovery, interrupted transfers,
physical ARM64 devices and full course workflows remain unverified.
Active documents are journaled immediately, edited text after 250 ms of idle
typing, and application backgrounding forces another session save. This reduces
loss after process recreation; an Android lifecycle test is still required.

Qt implementation reference: [Android content file engine, Qt 6.11.1](https://github.com/qt/qtbase/blob/v6.11.1/src/plugins/platforms/android/androidcontentfileengine.cpp).
